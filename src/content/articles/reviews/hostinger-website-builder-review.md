## 我们做了什么

为了给出一个不靠厂家宣传的使用结论，我们用 Hostinger Website Builder 的 AI 生成器，为 6 个不同行业的场景各做了一个站点：

1. 本地咖啡烘焙工作室（需要展示产品与预约）
2. 独立咨询顾问（个人品牌 + 服务介绍）
3. 小型驾校（课程介绍 + 报名表单）
4. 家政服务公司（服务范围 + 在线预约）
5. 手作皮具工作室（产品图库 + 下单意向）
6. 健身私教（课程包 + 联系方式）

每个站点都记录了从"输入描述"到"可以上线"的完整耗时，并记录过程中的卡点。

## AI 生成环节：90 秒出稿

输入方式是一句话描述加几个关键词。以咖啡工作室为例：

```
输入：本地咖啡豆烘焙工作室，提供新鲜烘焙的单一产地咖啡豆，
      支持线上预订与门店自取，主打小批量手工烘焙。
关键词：精品、手作、本地、新鲜
```

点击生成后，**平均 87 秒**出稿，6 个案例最快 71 秒、最慢 118 秒。

生成的初稿包含：

| 元素 | 是否生成 | 质量评价 |
| --- | --- | --- |
| 首页结构（Hero + 特色 + 产品 + 联系） | 是 | 结构合理，符合行业惯例 |
| 文案草稿 | 是 | 通顺但通用，含"我们提供优质服务"这类空话 |
| 配图 | 是 | 来自内置图库，与行业相关但明显是素材图 |
| 配色方案 | 是 | 按行业推荐，咖啡用了暖棕，驾校用了蓝 |
| 字体组合 | 是 | 保守但不出错 |
| 移动端适配 | 是 | 自动完成，实测无布局错乱 |
| 联系表单 | 是 | 可用 |
| SEO 元信息 | 是 | 标题与描述已填，但需要重写 |
| 品牌 Logo | 否 | 只给了一个字母组合占位 |
| 真实产品图 | 否 | 必须自己上传 |
| 具体业务细节 | 否 | 需要手工填写 |

**重要的是理解 AI 做了什么、没做什么。** 它给的是一个结构正确、排版合规、移动端可用的骨架。它没有做的是注入你的业务实质——因为那需要你的输入。

## 从生成到上线：26 分钟

以咖啡工作室为例的完整时间线：

| 环节 | 耗时 | 说明 |
| --- | --- | --- |
| AI 生成初稿 | 1.5 分钟 | 无需操作 |
| 替换为真实产品图 | 9 分钟 | 上传 12 张图，调整裁切 |
| 重写全部文案 | 11 分钟 | 把"优质服务"改成具体卖点与烘焙日期说明 |
| 调整品牌色与字体 | 2 分钟 | 从内置方案里选，不支持自定义色值 |
| 绑定域名 | 2 分钟 | 有免费域名，直接连接 |
| 上线检查（移动端 + 表单） | 1 分钟 | 无问题 |

**总计约 26 分钟**，其中 20 分钟花在"替换内容"上，AI 的部分只占 1.5 分钟。

这个比例本身就是结论：**AI 省下的是结构设计和排版的时间，不是内容创作的时间。** 如果你的内容本来就是空的，AI 帮不上忙。

## 做得比预期好的三处

### 一、移动端适配是真的自动

很多建站工具的"响应式"实际是缩放，在手机上会有文字过小或按钮拥挤的问题。Builder 生成的结果在 iPhone 13 到 15 Pro Max 的模拟尺寸下都没有出现布局错乱，导航自动折叠为汉堡菜单，表单元素尺寸适配了触控。

我们额外测了横屏与平板尺寸，也没有异常。

### 二、内置的表单和预约是可直接用的

对服务业来说这是刚需。表单提交会发送邮件通知，数据在后台可查，不需要接第三方服务。驾校和家政两个案例直接用了内置预约功能，配置耗时各约 3 分钟。

这个环节在 WordPress 里通常需要装 Contact Form 7 或 WPForms，然后额外配置。

### 三、图片处理是自动的

上传的原始图片会被自动压缩、生成多尺寸响应式版本。我们上传了一张 4.2MB 的相机原片，压缩后 WebP 版本是 187KB，画质在网页显示尺寸下看不出损失。这一项如果手动做，需要额外的图片处理流程。

## 必须人工介入的三处

### 一、文案永远是通用的

AI 生成的文案有一个可识别的模式：它会用行业标准表述填充每个位置。咖啡工作室得到的是"我们精选优质咖啡豆，为您带来独特风味体验"。

这句话没有错，但也没有信息量。真正能带来转化的是"每周三、周六烘焙，下单后 24 小时内发货"这种具体承诺。

**AI 不会知道你的具体业务细节，这部分永远要你自己写。** 在我们的 6 个案例中，文案重写占了总耗时的一半以上。

### 二、品牌视觉只能在内置方案里选

配色和字体是从预设方案里挑的，不支持输入自定义色值（比如你的品牌手册规定的主色）。

对于已经有品牌规范的用户，这是个硬限制。甲方给了一份 VI 手册，你无法把它实施到 Builder 上。

### 三、SEO 结构控制有限

可以设置每页的标题和描述，但无法精细控制 URL 结构、无法编辑结构化数据、无法加自定义 schema。内置的 SEO 工具是"基础够用"级别——如果你的核心策略是内容 SEO，这个限制会很快成为障碍。

## 什么时候该用 Builder，什么时候不该

### 该用

- 你的目标是**尽快拿到一个能看能用的官网**，且不打算深度运营
- 业务是**本地服务业**（餐饮、健身、家政、咨询、驾校），页面数量在 10 页以内
- 你需要**内置的预约或表单**功能，不想配置第三方插件
- 完全没有技术背景，也不打算学

### 不该用

- 你的核心策略是**内容 SEO**，需要长期产出文章矩阵
- 你**已经有品牌规范**，需要精确实施自定义配色与字体
- 你计划**长期运营并可能更换平台**——Builder 的页面无法导出，迁移只能重建
- 你需要**电商功能**且商品超过百件、有复杂变体

## 最终结论

Website Builder 是一款定位清晰的产品：它把"从零到一个能上线的网站"这个过程的门槛降到了接近零。

26 分钟上线一个站点，这个效率在传统 WordPress 流程下是做不到的——即使你熟悉 WordPress，安装、选主题、配置插件、调样式，也至少要两三个小时。

但它的代价同样清晰：**你放弃了控制权和迁移自由**。页面无法导出，SEO 结构控制有限，品牌视觉受限于预设方案。

所以我们的建议是按目标分：

| 你的目标 | 选择 |
| --- | --- |
| 快速上线一个本地服务官网 | Website Builder |
| 需要卖货、有 10 到 50 个 SKU | Website Builder Business |
| 要长期做内容 SEO | Premium 共享主机 + WordPress |
| 要给客户交付、需要交付后能改 | Premium 共享主机 + WordPress |

一条实用建议：**Builder 的 30 天退款期是一个低风险的试用窗口**。花 25 元买一个月，用它生成初稿看看效果，如果不适合，退款后转向 WordPress。生成过程本身也能帮你理清站点的页面结构——这份结构在 WordPress 里同样有用。
